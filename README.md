# AI開発クリニック

AI駆動開発の課題をもとに、改善案や工夫をカルテにまとめるワークショップ用アプリ。

## 画面

- `/`：プロジェクト概要・今回の課題・ワークの進め方を確認する入口です。「カルテを選んでワークを始める」から一覧へ進みます。このページはRedisに接続せずに読めます。
- `/?g=1`〜`/?g=4`：選んだカルテの詳細・編集画面です。具体的な出来事と発言を読み、「着目した問題」「原因の仮説」「試す処方」を記入します。何を問題と捉えるかは参加者が選び、事実と推測を分け、処方には効果の確かめ方も含めます。3項目は1つの「カルテを保存」ボタンで一括保存します。
- `/overview`：4つのカルテを選ぶ・共有する画面です。スマートフォンでは横スワイプ・左右ボタンで選び、「カルテを開く」で詳細へ進みます。PCでは問題・仮説・処方を含む2列の共有一覧を表示します。プロジェクト概要への戻りリンクを設けています。全員がすべてのカルテを閲覧・編集できます。
- 管理画面・ログイン・公開切り替え・タイマーはありません。カルテは最初から全グループに公開されます。

5秒ごとに最新の内容を反映しますが、入力中の文章は上書きしません。

## 共有編集とデータ

- 問題・仮説・処方は1回の操作で保存します。3項目の版番号をRedisのLuaスクリプトで確認し、どれかが更新済みなら全項目を保存せず、最新の文章と下書きを確認できます。
- 未保存の入力は編集中の画面内だけに保持し、端末には保存しません。保存に失敗した場合も、画面を閉じたり再読み込みしたりすると未保存の入力は消えます。再読み込みや再訪問時は共有の保存済みデータを表示します。保存済みの内容はほかの参加者にも反映されます。
- 保存先は `board:1`〜`board:4`。保存ごとに7日間のTTLを設定します。
- ワークショップ当日の前にRedisのデータをリセットするため、旧版のデータ・APIとの互換処理は持ちません。
- URLを知る参加者が閲覧・編集できるワークショップ向けの構成です。実際の案件名や顧客名は書かないでください。

## Vercel設定

画面はNext.js App Router・React・TypeScript、APIはRoute Handlers、保存はUpstash Redisです。

1. GitHubリポジトリをVercelにインポートします。ルートはリポジトリ直下です。`vercel.json` でNext.js・`npm ci`・`npm run build`・出力先 `.next` を指定します。Node.jsは22以上を使用します。
2. MarketplaceからUpstash Redisを追加してプロジェクトに接続します。以下のREST接続情報がProductionにも設定されていることを確認してください。

| URLの変数 | トークンの変数 |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | `UPSTASH_REDIS_REST_TOKEN` |
| `KV_REST_API_URL` | `KV_REST_API_TOKEN` |

`example_KV_REST_API_URL` / `example_KV_REST_API_TOKEN` のような接頭辞付きも自動検出します（`example_` は架空の例）。同じ接頭辞・同じ種類のURLとTOKENを使用します。READ_ONLY_TOKENとTCP用REDIS_URLは使用しません。複数の接続先がある場合は、接頭辞なしの標準変数名で使用先を明示してください。実際の変数名や値をソースやドキュメントに記録しないでください。

3. 環境変数を変更した後は再デプロイします。合言葉の設定は不要です。
4. `/?g=1`〜`/?g=4` を各参加者へ配布します。全員が同じカルテ用URLから参加できます。

公開済みプロジェクトでは、GitHubの最新コミットが反映されたProductionデプロイがReadyになったことを確認します。

## ローカル開発

```sh
npm install
Copy-Item .env.example .env.local
# .env.local に検証用Redisの接続情報を設定
npm run dev
```

`http://localhost:3000` を開きます。Next.jsが `.env.local` を自動で読み込みます。上記のコピーはPowerShell用です。macOS/Linuxでは `cp .env.example .env.local` を使ってください。ローカルでも実際のRedisを使用するため、開発用に別のデータベースを推奨します。認証情報がなくても画面は開けますが、カルテの取得・保存にはRedisが必要です。

```sh
npm test
npm run check
npm run build
# ビルドした本番相当のアプリを起動
npm start
```

APIテストはRedisのテスト用アダプターを使用し、共有編集の競合、入力検証、3項目一括保存、TTLを検証します。Luaスクリプトと実Redisとの接続はデプロイ後に確認してください。

ブラウザーテストは通信をテスト用データに置き換えるため、Redis認証情報なしで実行できます。保存・再読み込み・2画面の競合・通信失敗時の入力保持・再読み込み時の保存済み回答表示・幅375pxを確認します。

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

## 開発時の構成

- `src/app/`: ページ、共通レイアウト、CSS、`api/[route]/route.ts` のAPI入口。
- `src/components/`: カルテ編集、一覧、共通ヘッダー。
- `src/lib/`: 教材データ、ブラウザー通信・型定義、既存APIを呼ぶ接続処理。
- `lib/`: Redis接続、入力検証、Luaによる一括保存。
- `test/`: API・接続処理のテスト。`test/browser/` はPlaywrightによるブラウザーテスト。

一覧のURLは `/overview`、各カルテは `/?g=1`〜`/?g=4` です。

## API

| メソッド・パス | 内容 |
| --- | --- |
| `GET /api/karte?group=N` | 指定カルテの問題・仮説・処方・版番号を取得 |
| `PUT /api/karte?group=N` | `{ issue, root, remedy, revisions: { issue, root, remedy } }` で3項目を一括更新。各項目2,000文字以内。いずれかの版番号が競合したら409で全更新を中止 |
| `GET /api/all` | 全カルテの問題・仮説・処方を取得 |

APIは常にJSONを返し、キャッシュを無効にしています。入力値は画面でtextContentを使って表示します。

## デプロイ後の確認

- 2台で同じカルテを開き、1つの保存ボタンで問題・仮説・処方を一括保存できること
- 再読み込みして保存済みの内容が残ること
- 同じ欄を2台で編集し、後の保存で競合確認が出て入力が消えないこと
- 一覧に場面の出来事・着目した問題・原因の仮説・試す処方が表示されること
- 一覧の各カードから直接グループの入力画面へ進めること
- 375px幅で入力・閲覧できること
