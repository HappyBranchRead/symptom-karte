# AI開発クリニック

AI駆動開発の課題をもとに、改善案や工夫をカルテにまとめるワークショップ用アプリ。

## 画面

- `/`：プロジェクト概要・今回の課題・ワークの進め方を確認する入口です。「カルテを選んでワークを始める」から一覧へ進みます。このページはRedisに接続せずに読めます。
- `/?g=1`〜`/?g=4`：選んだカルテの詳細・編集画面です。「症状・課題」（固定）と「原因分析」「処方」の3項目に絞っています。症状には具体的な出来事と影響を記載し、原因や解決策は参加者が考えます。原因分析と処方は入力欄に直接書き込み、1つの「カルテを保存」ボタンでまとめて反映します。
- `/overview`：4つのカルテを選ぶ・共有する画面です。スマートフォンでは横スワイプ・左右ボタンで選び、「カルテを開く」で詳細へ進みます。PCでは原因分析・処方を含む2列の共有一覧を表示します。プロジェクト概要への戻りリンクを設けています。全員がすべてのカルテを閲覧・編集できます。
- 旧 `/overview.html` と `/admin.html` は一覧画面へ転送します。管理画面・ログイン・公開切り替え・タイマーはありません。カルテは最初から全グループに公開されます。

5秒ごとに最新の内容を反映しますが、入力中の文章は上書きしません。

## 共有編集と既存データ

- 原因分析と処方は1回の操作でまとめて保存します。両方の版番号をRedisのLuaスクリプトで確認し、どちらかをほかの人が更新していたら、両方とも保存せずに最新の文章と下書きの確認を促します。途中の片方だけが保存されることはありません。旧版の欄ごとの保存APIとも互換性を保っています。
- 下書きは端末内に残り、通信に失敗しても再保存できます。保存済みの内容はほかの参加者にも反映されます。
- 旧版の「一番の原因」と「選んだ打ち手」は、それぞれ原因分析と処方として引き続き表示します。
- 気づきの投稿欄・投稿一覧・投稿件数は画面から外しました。旧版の投稿、原因、つながりの保存データは削除せず、元の有効期限まで残しています。
- 保存先は `board:1`〜`board:4`。保存ごとに7日間のTTLを設定します。端末内の下書きも7日間で期限切れになります。
- URLを知る参加者が閲覧・編集できるワークショップ向けの構成です。実際の案件名や顧客名は書かないでください。

## Vercel設定

画面はNext.js App Router・React・TypeScript、APIはRoute Handlers、保存はUpstash Redisです。

1. GitHubリポジトリをVercelにインポートします。ルートはリポジトリ直下です。`vercel.json` でNext.js・`npm ci`・`npm run build`・出力先 `.next` を指定し、旧構成の `public` 配信設定を上書きします。Node.jsは22以上を使用します。
2. MarketplaceからUpstash Redisを追加してプロジェクトに接続します。以下のREST接続情報がProductionにも設定されていることを確認してください。

| URLの変数 | トークンの変数 |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | `UPSTASH_REDIS_REST_TOKEN` |
| `KV_REST_API_URL` | `KV_REST_API_TOKEN` |

`example_KV_REST_API_URL` / `example_KV_REST_API_TOKEN` のような接頭辞付きも自動検出します（`example_` は架空の例）。同じ接頭辞・同じ種類のURLとTOKENを使用します。READ_ONLY_TOKENとTCP用REDIS_URLは使用しません。複数の接続先がある場合は、接頭辞なしの標準変数名で使用先を明示してください。実際の変数名や値をソースやドキュメントに記録しないでください。

3. 環境変数を変更した後は再デプロイします。合言葉の設定は不要です。旧版の `ADMIN_PASS` は使用しないため削除できます。
4. `/?g=1`〜`/?g=4` を各参加者へ配布します。全員が同じカルテ用URLから参加できます。

公開済みプロジェクトでは、GitHubの最新コミットが反映されたProductionデプロイがReadyになったことを確認します。

## ローカル開発

```sh
npm install
Copy-Item .env.example .env.local
# .env.local に検証用Redisの接続情報を設定
npm run dev
```

`http://localhost:3000` を開きます。Next.jsが `.env.local` を自動で読み込みます。上記のコピーはPowerShell用です。macOS/Linuxでは `cp .env.example .env.local` を使ってください。ローカルでも実際のRedisを使用するため、開発用に別のデータベースを推奨します。認証情報がなくても画面は開けますが、カルテの取得・保存にはRedisが必要です。

```sh
npm test
npm run check
npm run build
# ビルドした本番相当のアプリを起動
npm start
```

APIテストはRedisのテスト用アダプターを使用し、共有編集の競合、入力検証、既存データの読み込み、TTL、旧投稿APIの互換性を検証します。Luaスクリプトと実Redisとの接続はデプロイ後に確認してください。

ブラウザーテストは通信をテスト用データに置き換えるため、Redis認証情報なしで実行できます。保存・再読み込み・2画面の競合・通信失敗時の下書き保持・幅375px・旧URLを確認します。

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

## 開発時の構成

- `src/app/`: ページ、共通レイアウト、CSS、`api/[route]/route.ts` のAPI入口。
- `src/components/`: カルテ編集、一覧、共通ヘッダー。
- `src/lib/`: 教材データ、ブラウザー通信・型定義、既存APIを呼ぶ接続処理。
- `lib/`: Redis接続、入力検証、Luaによる一括保存。既存の保存形式を維持します。
- `test/`: API・接続処理のテスト。`test/browser/` はPlaywrightによるブラウザーテスト。

一覧の標準URLは `/overview` です。既存の `/overview.html` と `/admin.html` は転送し、`/?g=1`〜`/?g=4` はそのまま利用できます。

## API

| メソッド・パス | 内容 |
| --- | --- |
| `GET /api/karte?group=N` | 指定カルテの投稿・まとめ・版番号を取得 |
| `POST /api/posts?group=N` | 旧版との互換性のため残している投稿API。現在の画面では使用しません |
| `PUT /api/karte?group=N` | `{ root, remedy, revisions: { root, remedy } }` でカルテを一括更新。各項目2,000文字以内。いずれかの版番号が競合したら409で更新を中止。旧版の `{ field, value, revision }` も受付 |
| `GET /api/all` | 全カルテの投稿・まとめを取得 |

旧版のログイン・フェーズ・リセットAPIは廃止しました。APIは常にJSONを返し、キャッシュを無効にしています。入力値は画面でtextContentを使って表示します。

## デプロイ後の確認

- 2台で同じカルテを開き、1つの保存ボタンで原因分析と処方を一括保存できること
- 再読み込みして保存済みの内容が残ること
- 同じ欄を2台で編集し、後の保存で競合確認が出て入力が消えないこと
- 一覧に現在の症状・原因分析・処方だけが表示されること
- 一覧の各カードから直接グループの入力画面へ進めること
- 375px幅で入力・閲覧できること
