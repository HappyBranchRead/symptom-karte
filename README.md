# 症状カルテ

AI駆動開発のケーススタディ用グループワーク補助アプリ。タイトルは仮称です。

## 画面

- `/`：参加するグループを選択します。
- `/?g=1`〜`/?g=4`：自分たちの症状・問い・投稿・まとめだけに集中するページです。同じグループの全員が自分のスマホから「原因・気づき」「打ち手のアイデア」を投稿できます。
- `/overview.html`：4つの症状をカードで一覧表示。カードから詳細を拡大でき、詳細内の「グループに参加して書き込む」から各グループの入力画面へ移動できます。発表にも使用できます。グループ活動ページへの戻りリンクがあります。
- 旧 `/admin.html` は一覧画面へ転送します。ログイン、管理画面、公開フェーズ、タイマー、ヒント機能はありません。全グループの投稿・まとめを最初から閲覧できます。

投稿は5秒ごとに反映され、入力中の下書きは上書きしません。タブを再表示すると再取得します。通信失敗時は下書きを残し、投稿ボタンから再試行できます。一覧画面の「記録を保存」で全件のMarkdownをダウンロードできます。

## 同時利用と既存データ

- 投稿は1件ずつ独立したIDでRedisハッシュに追加し、同時投稿で互いの発言が消えないようにしています。同じIDで再試行しても投稿数は増えません。
- 「一番の原因」「選んだ打ち手」はそれぞれ独立した版番号で保存します。編集中にほかの人が更新していた場合は自動で上書きせず、最新の内容と自分の下書きを確認して再保存できます。
- 旧版の `karte:1`〜`karte:4` は消さずに読み込みます。原因・つながりは「これまでの議論」に、原因と打ち手のまとめは新しいまとめの初期値として表示します。
- 新しい保存先は `board:1`〜`board:4`。投稿・まとめの書き込みごとに7日間のTTLを設定します。端末内の下書きも7日間で期限切れになります。
- 投稿・まとめにはログイン認証を設けていません。URLを知っている参加者が閲覧・投稿・編集するワークショップ向けです。架空事例だけを記載してください。

## Vercel設定

画面はHTML/CSS/JavaScript、APIはVercel Functions、保存はUpstash Redisです。

1. GitHubリポジトリをVercelにインポートします。Presetは **Other**、ルートはリポジトリ直下、Build Commandは空欄、Output Directoryは `public`、Install Commandは `npm install` です。Node.jsは22以上を使用します。
2. MarketplaceからUpstash Redisを追加してプロジェクトに接続します。以下のREST接続情報がProductionにも設定されていることを確認してください。

| URLの変数 | トークンの変数 |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | `UPSTASH_REDIS_REST_TOKEN` |
| `KV_REST_API_URL` | `KV_REST_API_TOKEN` |

`example_KV_REST_API_URL` / `example_KV_REST_API_TOKEN` のような接頭辞付きも自動検出します（`example_` は架空の例）。同じ接頭辞・同じ種類のURLとTOKENを使用します。READ_ONLY_TOKENとTCP用REDIS_URLは使用しません。複数の接続先がある場合は、接頭辞なしの標準変数名で使用先を明示してください。実際の変数名や値をソースやドキュメントに記録しないでください。

3. 環境変数を変更した後は再デプロイします。合言葉の設定は不要です。旧版の `ADMIN_PASS` は使用しないため削除できます。
4. `/?g=1`〜`/?g=4` を各グループへ配布します。全員が同じグループ用URLから参加できます。

公開済みプロジェクトでは、GitHubの最新コミットが反映されたProductionデプロイがReadyになったことを確認します。

## ローカル開発

```sh
npm install
cp .env.example .env.local
# .env.local に検証用Redisの接続情報を設定
node --env-file=.env.local dev-server.mjs
```

`http://localhost:3000` を開きます。ローカルでも実際のRedisを使用するため、開発用に別のデータベースを推奨します。

```sh
npm test
npm run check
```

APIテストはRedisのテスト用アダプターを使用し、同時投稿、再送、まとめの競合、入力検証、既存データの読み込み、TTLを検証します。Luaスクリプトと実Redisとの接続はデプロイ後に確認してください。

## API

| メソッド・パス | 内容 |
| --- | --- |
| `GET /api/karte?group=N` | 指定グループの投稿・まとめ・版番号を取得 |
| `POST /api/posts?group=N` | `{ id, text, kind }` を投稿。textは500文字以内、kindはcauseまたはremedy、idは端末で生成するUUID |
| `PUT /api/karte?group=N` | `{ field, value, revision }` でまとめを更新。fieldはrootまたはremedy、valueは2,000文字以内。競合時は409 |
| `GET /api/all` | 全グループの投稿・まとめを取得 |

旧版のログイン・フェーズ・リセットAPIは廃止しました。APIは常にJSONを返し、キャッシュを無効にしています。入力値は画面でtextContentを使って表示します。

## デプロイ後の確認

- 2台のスマホで同じグループを開き、同時に投稿して両方が残ること
- 再読み込みして投稿・まとめが残ること
- 同じまとめを2台で編集し、後の保存で確認メッセージが出ること
- 他グループの入力を待たずに一覧と詳細を閲覧できること
- 一覧から自分のカルテに戻れること
- 375px幅で入力・閲覧でき、Markdownを保存できること
